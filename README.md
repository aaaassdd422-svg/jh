# دليل الزائر — أهلاً بكم زوار الحسين

واجهة عربية/إنجليزية/فارسية متجاوبة مبنية بـ HTML وCSS وJavaScript دون build step. المشروع يضم الخريطة، مساعداً محلياً أو مساعداً توليدياً اختيارياً، فهرس أدعية، تقويم مناسبات، ومعرض صور بإسناد وترخيص.

## التشغيل المحلي

افتح `index.html` أو قدّمه من localhost/HTTPS. يمكن تشغيل عناصر الواجهة الأساسية محلياً، لكن المكتبات والخريطة والبحث الجغرافي والتوجيه والصور والمساعد المولد تحتاج إنترنت. خريطة OSM هنا غير مخزنة للعمل دون اتصال؛ زر التنزيل لا ينشئ حزمة خرائط offline. خدمات OSM/Nominatim/OSRM العامة لها حدود استخدام وتوفر منفصلان.

## المساعد النصي والصوتي

من دون إعداد Supabase يظل المساعد في وضع محلي محدود يشرح وظائف الدليل. لتمكين الذكاء الاصطناعي:

1. أنشئ مشروع Supabase، ثم نفّذ `supabase/schema.sql` في SQL Editor بعد مراجعة السياسات مع مسؤول المشروع.
2. فعّل Anonymous Sign-Ins من إعدادات Authentication. الواجهة تنشئ جلسة مجهولة حتى تقبل Edge Function التي تتطلب JWT. الجلسة المجهولة مرتبطة بالمتصفح الحالي ولا تمثل حساباً قابلاً للاسترداد.
3. المشروع HTML ثابت بلا bundler ولا يقرأ `.env` وقت التشغيل. اضبط متغيري النشر العامين `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`، واجعل الاستضافة تحقنهما في `window.HALA_RUNTIME_CONFIG` قبل تحميل `config.js`؛ أو ضع القيمتين العامتين يدويًا في `config.js`. المفتاح publishable/anon فقط مسموح للمتصفح. لا تضع مفتاح Gemini أو service-role في الواجهة. `.env.example` يوضح أسماء القيم ولا يحتوي أسرارًا.
4. عيّن أسرار Edge Function من لوحة Supabase أو CLI: `ANTHROPIC_API_KEY` (أو `GEMINI_API_KEY` للتوافق مع الإعداد القديم)، و`SUPABASE_SERVICE_ROLE_KEY` و`SUPABASE_ANON_KEY` إذا لم تكن متاحة تلقائيًا في بيئة Edge Functions، و`APP_ORIGINS` بقائمة origins الفعلية مفصولة بفواصل، مثل `https://example.org,https://www.example.org` من دون مسارات. يدعم التطوير `http://localhost` و`http://127.0.0.1` بأي منفذ. `ANTHROPIC_MODEL` اختياري؛ الافتراضي `claude-sonnet-5-5`. `GEMINI_MODEL` اختياري عند استخدام Gemini.
5. انشر `supabase/functions/pilgrim-assistant` بالأمر `supabase functions deploy pilgrim-assistant`. تحقّق من أسرار النشر ومن origin الفعلي عبر logs قبل الإعلان عن تفعيل الخدمة.

الواجهة ترسل نص المحادثة إلى Edge Function؛ الخادم وحده يستدعي Anthropic عند ضبط `ANTHROPIC_API_KEY`، أو Gemini عند ضبط مفتاحه القديم، يقيّد حجم الرسائل ومعدلها، ويعيد مصادر مطابقة لكلمات البحث. الرد ليس فتوى ولا ضماناً لصحة كل استنتاج نموذجي؛ راجع المصدر بنفسك. صوت الإدخال يستخدم Web Speech API عندما يدعمه المتصفح، ويمرر النص الناتج للمساعد. صوت الإخراج يستخدم SpeechSynthesis المحلية؛ نوع الصوت وجودة العربية يعتمدان على نظام التشغيل والمتصفح. لا توجد خدمة Whisper مدمجة.

## الحسابات برقم الهاتف

يتطلب تسجيل الحساب إعداد عنوان المشروع والمفتاح العام كما أعلاه، وتفعيل Phone Auth وSMS OTP في Supabase، ثم تطبيق `supabase/schema.sql` والترحيلات بالترتيب. اسم المستخدم يُحفظ في جدول `profiles` ويُتحقق من تفرّده دون حساسية لحالة الأحرف. طول كلمة المرور في النموذج 8 أحرف على الأقل؛ المصادقة وحدها تتعامل مع كلمة المرور. صورة الحساب تحتاج إعداد bucket وسياسات Storage قبل تفعيل رفع الصور.

## المكتبة الروحية والتقويم

`spiritual-data.js` يحتوي فهرساً قصيراً وروابط إلى صفحات مصادرها، لا نسخاً كاملة للأدعية. يعرض الاقتباسات القصيرة مع الإحالة، ويتجنب حسم اختلاف الإسناد. التقويم يستخدم تقويم أم القرى في المتصفح ويعرض تواريخ مرجع واحد فقط؛ قد تختلف التواريخ والروايات. إشعارات المتصفح تعمل بعد الإذن، أثناء بقاء الصفحة مفتوحة فقط، ولا توجد إشعارات دفع مجدولة في الخلفية.

## معرض الصور

المعرض يسحب الصور عند الطلب من Wikimedia Commons باستخدام lazy loading، ويعرض اسم المصور وصفحة الملف ورابط الترخيص المحدد. الصور الخارجية قد تتغير أو تتوقف؛ اضغط اسم الصورة/المؤلف لفتح صفحة المصدر. لا توجد صور مولدة أو منسوبة لأشخاص مقدسين.

## الأمان والنطاق

`supabase/schema.sql` هو المخطط التأسيسي الحالي ويُطبّق مرة واحدة على قاعدة جديدة؛ ثم طبّق ملفات `supabase/migrations/` تصاعديًا. الترحيلات تضيف View للاستضافات المعتمدة، RLS إضافية، صلاحيات مضيف، سعة حجز ذرية، إشعارات، Storage، Realtime، خدمات، وإعدادات وسجل محادثات خاصًا بالمستخدم. تعيين دور المضيف/المشرف يجب أن يتم من قناة إدارية موثوقة؛ لا تمنح الأدوار من الواجهة. افحص سياسات المشروع وإعدادات Auth وقيود SMS ومزوّدي الخدمة قبل بيانات الإنتاج. يتحقق RPC الحجز من ذروة الإشغال داخل فترة الوصول والمغادرة تحت قفل للمكان لمنع الحجز الزائد. حقل الأماكن المتاحة الظاهر في الدليل يظل السعة المعلنة من المضيف؛ قرار قبول كل فترة يستند إلى الحجوزات المتداخلة الفعلية.

## الفحص

شغّل فحص الصياغة للملفات العميلة باستخدام `node --check app.js`, `node --check spiritual.js`, و`node --check spiritual-data.js`. ملف Edge Function يستخدم Deno وSupabase Edge Runtime، لذلك افحصه كذلك عبر `deno check` بعد إعداد Deno/الاستيراد الشبكي.

## تحديثات المساعد

يحفظ التطبيق آخر 40 رسالة محلياً، وللمستخدم المسجل يحفظ المحادثة أيضًا في جداول Supabase الخاصة به مع البحث والفتح والحذف من زر المحادثات. حذف سجل المحادثة يزيل رسائلها التابعة. توجد أزرار نسخ/استماع/إعادة الإجابة لكل رد. عند غياب إعداد Supabase يعمل وضع دليل محلي محدود يجيب عن إرشادات ثابتة للواجهة فقط، ولا يدّعي أنه ذكاء اصطناعي أو يملك بيانات حية. عند تفعيل الخدمة، فشل الشبكة أو الخدمة يظهر كخطأ صريح ولا يتحول إلى إجابة محلية مضللة. تدعم القراءة الصوتية الإيقاف المؤقت والاستكمال والإيقاف حسب دعم المتصفح. تعرّف الصوت وإخراج الصوت يعتمدان على Speech APIs في الجهاز، ولا تُرفع التسجيلات الصوتية.

## ربط بيانات الموقع

1. أنشئ مشروع Supabase ثم شغّل `supabase/schema.sql` مرة واحدة.
2. طبّق `supabase/migrations/20261001000100_production_data_layer.sql` ثم `20261001000200_services_settings_and_ai_history.sql`.
3. فعّل تسجيل الدخول بالهاتف ورموز SMS، واضبط origins في `APP_ORIGINS` وSecrets الخاصة بـ Edge Function كما أعلاه.
4. جهّز متغيرات النشر العامة الموضحة في `.env.example` ليحقنها المضيف في `window.HALA_RUNTIME_CONFIG` قبل `config.js`.
5. سجّل الدخول للاستخدام المتزامن: تظهر الاستضافات المنشورة والمفضلة والحجوزات والإشعارات من Supabase. يمكن للزائر إرسال موقع جديد للمراجعة، ويستخدم زر الحجز RPC ذريًا. الزيارات بلا اتصال بخدمة Supabase تحتفظ فقط بالمواقع والمفضلة المحلية الحالية؛ لا تُعرض على أنها سجلات خادمية.

المضيف الذي يملك الموقع يمكنه تعديل بياناته وإدارة طلبات الحجز. تعتمد RLS وRPC على `auth.uid()`، ويمنع المتصفح من إدراج الحجز مباشرة أو تعديل حقل حالة المراجعة. الصور في bucket الاستضافة عامة للعرض بعد النشر، بينما الصور الشخصية والوثائق خاصة. ملف `supabase/seed.test.sql` اختبار اختياري لبيئة مؤقتة فقط ويعمل داخل معاملة تنتهي بـ rollback.

## عمليات CRUD لبيانات الأماكن مع Supabase

التطبيق يتيح للمستخدم إدارة المواقع وخدمات الزائرين وحفظها في جدول `public.locations`. نوفر واجهات جاهزة في `services/dataService.js` تشمل `locations(client)` للجلب، و`createLocation(client,userId,input)` للإضافة، و`updateLocation(client,id,changes)` للتعديل، و`deleteLocation(client,id)` للحذف. يتم استدعاء عميل Supabase مع تغليف العمليات دائمًا داخل `try/catch` للتعامل مع الأخطاء بأمان:

```js
const client = window.HalaSupabase.getClient();
try {
  const rows = await window.HalaData.locations(client); // جلب الأماكن المصرح بها وفق RLS
  const created = await window.HalaData.createLocation(client, user.id, {
    name: 'موكب الإيثار', kind: 'mawkeeb', description: 'خدمات واستراحة للزوار', address: 'طريق يا حسين',
    latitude: 32.0, longitude: 44.0, services: ['ماء', 'طعام', 'استراحة'],
    capacity_total: 100, capacity_available: 50, service_status: 'available'
  });
  await window.HalaData.updateLocation(client, created.id, { name: 'موكب الإيثار والضيافة' });
  await window.HalaData.deleteLocation(client, created.id);
} catch (error) {
  console.error('خطأ في عمليات Supabase:', error.message);
}
```

الحقول المستخدمة تشمل `id` (UUID يُنشأ تلقائيًا من قاعدة البيانات)، و`owner_id`، و`name`، و`kind`، و`description`، و`latitude`، و`longitude`، و`services`، و`capacity_available`، و`service_status`، و`review_status`، و`created_at`. تفاصيل الهيكل والمفاتيح موضحة في `supabase/schema.sql` والترحيلات المرتبطة به.

### سياسات الأمان والحماية RLS

يُستخدم مفتاح الوصول العام للعميل (anon/publishable) فقط في المتصفح. لا تضع `service_role` في أي كود JavaScript عميل أو في مستودع Git. يتم تهيئة المفاتيح العامة من خلال متغيرات البيئة كما في `.env.example`: حيث يتم تمرير المتغيرات العامة `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` للواجهة عبر مساحة عامة أو حقنها في `window.HALA_RUNTIME_CONFIG` قبل تحميل `config.js`.

قواعد RLS على جدول `locations` الموضحة في `supabase/schema.sql` تفرض الخصوصية والأمان: الاستعلامات العامة تقرأ فقط الأماكن المعتمدة والمنشورة، بينما الأماكن الجديدة المضافة تتطلب مراجعة وتأخذ حالة `pending`. المستخدم يستطيع فقط تعديل وحذف الأماكن التي يملكها والمطابقة لمعرفه `auth.uid()`. لا يمكن للمستخدمين العاديين تعديل حقل `review_status` أو التلاعب بـ `owner_id`. وتتم معالجة الحجوزات والسعة الذرية عبر دوال RPC داخل قاعدة البيانات لضمان عدم حدوث حجز زائد.

جميع حسابات المستخدمين يتم التحقق منها عبر الرسائل النصية القصيرة SMS عبر Supabase Auth، لضمان المصداقية وحماية البيانات.
